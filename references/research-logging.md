# 调研记录规范

> 核心原则：**先存后整理，低摩擦，顺手保存。**
> 调研结果只存在对话里 = 没做过。原始数据先存下来，分类和提炼可以以后慢慢做。

---

## 1. 为什么要记录

调研中最容易丢失的不是结论，而是**原始数据和过程线索**：
- 搜了哪些关键词？在哪些平台搜的？
- 哪些结果被过滤掉了？为什么？
- 中间发现了什么意外线索？
- 原始 JSON 数据长什么样？

这些信息在调研当下觉得"记得住"，但一周后全忘。记录的目的不是写完美报告，而是**给未来的自己留足够的线索**。

---

## 2. 记录原则

| 原则 | 说明 |
|---|---|
| **先存后整理** | 原始数据直接扔 `raw/`，不需要分类、不需要命名规范、不需要立即分析 |
| **低摩擦** | 保存是调研流程的自然延伸——搜索命令结果直接重定向到文件，不是额外步骤 |
| **1 分钟规则** | 调研结束时只花 1 分钟填 `README.md` 的关键发现，不要求完整报告 |
| **碎片也有价值** | `notes.md` 可以是半句话、一个疑问、一个关键词，不需要结构化 |
| **不覆盖** | 每次调研新建目录，旧目录保留不动。后续整理在 `output/` 里做 |

---

## 3. 目录结构

```
knowledge-space/research-logs/
└── YYYY-MM-DD_议题名称/
    ├── README.md      # 调研概要（结束时花 1 分钟填）
    ├── notes.md       # 随手记（调研过程中随时追加）
    ├── raw/           # 原始数据（JSON、截图、HTML、下载的文件）
    └── output/        # 整理后的产出（报告、摘要、表格，以后慢慢填）
```

### 命名规则

- 目录名：`YYYY-MM-DD_议题名称`（日期自动生成，议题名称用简短中文）
- raw/ 内的文件：`<平台>_<动作>_<关键词>.json`，如 `xiaohongshu_search_AI编程.json`
- 不需要严格遵守命名——**存下来比命名正确重要**

---

## 4. 各文件用途与填写时机

### README.md — 结束时填（1 分钟）

| 字段 | 填写时机 | 要求 |
|---|---|---|
| 议题与目标 | 开始时（脚本自动生成模板，填一句话） | 为什么做这个调研 |
| 关键发现 | 结束时 | 3-5 条最有价值的发现，每条一句话 |
| 信息来源 | 过程中或结束时 | 平台、关键词、条数的表格 |
| 后续待整理 | 结束时 | 哪些 raw/ 数据值得进一步分析 |

**关键发现的写法**：不要写"调研了 XX 平台"，要写"发现 XX 平台上 YY 群体对 ZZ 的看法是 WW"。结论性的，不是过程性的。

### notes.md — 过程中随时写

不需要格式，想到什么写什么：
```
- 搜"AI编程"时发现"vibe coding"这个词，可能是个好关键词
- 小红书上这篇笔记点赞 3000 但内容很水，注意高赞≠高质量
- V2EX 上有人提到 SpecKit，但搜不到更多信息，可能需要换关键词
- 疑问：SDD 和 BDD 到底什么关系？
```

### raw/ — 搜索结果直接存

**最关键的习惯**：每个搜索命令的结果都重定向到文件：

```bash
# ❌ 不好：结果只在终端里，过了就没了
opencli xiaohongshu search "AI编程" --limit 20 -f json

# ✅ 好：结果同时存到文件和终端
opencli xiaohongshu search "AI编程" --limit 20 -f json | Tee-Object raw/xiaohongshu_search_AI编程.json
```

PowerShell 用 `Tee-Object`，Linux/Mac 用 `tee`。

截图、下载的图片、HTML 页面也直接扔 `raw/`。

### output/ — 以后慢慢整理

调研当下不需要填。后续有空时，从 raw/ 提取数据、做分析、写报告，放到 output/。可以是：
- 结构化的 Markdown 报告
- 数据表格（CSV/Excel）
- 可视化图表
- 提炼后的关键词列表

## 5. Agent 操作流程（集成到调研 SOP）

### 调研开始时（第 0 步，在关键词拆解之前）

```bash
# 1. 一键创建调研目录
python scripts/init_research.py "议题名称"
# 输出: ✅ 调研目录已创建: E:\...\research-logs\2026-09-06_议题名称

# 2. 把目录路径记下来，后续所有操作都基于这个目录
$researchDir = "E:\...\research-logs\2026-09-06_议题名称"
```

### 调研过程中

```bash
# 每个搜索命令都用 Tee-Object 存到 raw/
opencli xiaohongshu search "关键词" --limit 20 -f json |
  Tee-Object "$researchDir\raw\xiaohongshu_search_关键词.json"

# 有想法随时追加到 notes.md
Add-Content "$researchDir\notes.md" "- 发现：XXX"

# 下载的图片/文件直接存到 raw/
opencli xiaohongshu download <note_url> --output "$researchDir\raw\"
```

### 调研结束时（最后一步，花 1 分钟）

```bash
# 编辑 README.md，填写关键发现和信息来源
# 不需要写完整报告，3-5 条关键发现 + 来源表格即可
```

## 6. 与调研 SOP 的集成点

在 `research-sop.md` 的 8 步 SOP 中，记录规范嵌入以下位置：

| SOP 步骤 | 记录动作 |
|---|---|
| 0. 调研准备 | 运行 `init_research.py` 创建目录 |
| 1. 议题拆解 | 把关键词矩阵存到 `notes.md` |
| 2-4. 批量搜索/新词捕获 | 每个搜索结果 `Tee-Object` 到 `raw/` |
| 5. 去重清洗 | 中间结果存 `raw/`（带 `_deduped` 后缀） |
| 6. 结构化分类 | 分类结果存 `output/`（如果当时就整理了） |
| 7. 分层总结 | 总结存 `output/`，关键发现回填 `README.md` |
| 8. 经验沉淀 | 新经验追加到 skill 的 `references/`，不是调研目录 |

## 7. 常见问题

### Q: 每次调研都要建目录吗？会不会太碎？

A: 是的，每次建一个。碎比丢好。后续可以在 `output/` 里把多个相关调研的结果整合成一份报告。目录按日期排列，本身就是时间线。

### Q: raw/ 里文件太多太乱怎么办？

A: 不需要整理。raw/ 的定位就是"数据垃圾桶"——什么都往里扔，需要的时候再翻。如果某个调研的数据特别多，可以在 raw/ 里再建子目录（如 `raw/xiaohongshu/`、`raw/zhihu/`），但不是必须。

### Q: 调研结束后一定要填 README.md 吗？

A: 尽量填，但只花 1 分钟。哪怕只写 3 条关键发现，也比什么都不填强。如果实在没时间，至少把信息来源表格填上（平台+关键词+条数），这样以后看到这个目录知道里面是什么。

### Q: 后续整理时，原始数据要移动吗？

A: 不要移动 raw/ 里的文件。整理后的产出放 output/，raw/ 保持原样作为原始证据。如果 output/ 里的报告引用了 raw/ 的数据，写清楚文件名即可。

### Q: 可以把多个小调研合并到一个目录吗？

A: 可以。如果是同一个大议题下的多次调研（如"AI编程工具调研"分了小红书、知乎、Reddit 三次），可以用同一个目录，每次搜索结果都存到 raw/，notes.md 按日期分段。但如果议题差异大（如"AI编程"和"上海周末去哪"），还是分开建目录。

## 8. 快速检查清单

每次调研结束前，问自己：

- [ ] 调研目录创建了吗？（`init_research.py`）
- [ ] 搜索结果都存到 `raw/` 了吗？（用 `Tee-Object`）
- [ ] 过程中的想法和疑问记到 `notes.md` 了吗？
- [ ] `README.md` 填了关键发现（至少 3 条）吗？
- [ ] 信息来源表格填了吗？

如果以上都做了，这次调研的记录就合格了。**不需要完美，需要存在。**
