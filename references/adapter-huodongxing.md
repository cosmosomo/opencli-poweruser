# 活动行适配器经验

> 验证日期：2026-09-17（探活复核 2026-09-17，`opencli huodongxing --help`）
> 版本：opencli v1.8.7
> 结论：**只有 `events` 一条命令，且只返回活动索引**。真正有价值的赞助商 / 展商 / 演讲嘉宾 / 议程
> **不在适配器输出里**，必须拿 `id`/`url` 再走 `opencli browser` 穿透详情页。反爬中等：连续调用会撞 busy 页。

## 认证方式

无需登录（浏览与搜索免登录；报名/购票才需要）。
`Browser: yes` —— 走 Browser Bridge，**不是** Node 直连的公开 API 适配器，daemon 必须在跑。

## 可用命令（全部）

| 命令 | 用途 |
|---|---|
| `events` | [read] 活动搜索（按标签 / 城市 / 日期 / 线上线下 / 名称过滤） |

**就这一条。** 没有 detail、没有 organizer、没有 speaker 命令。

### events 参数（`--help` 实录）

| 参数 | 含义 | 默认 |
|---|---|---|
| `--tag [value]` | 活动标签，例如 `AI` | 空 |
| `--city [value]` | 城市名，例如 `北京` / `上海` / `全部` | `全部` |
| `--date [value]` | 开始日期 `YYYY-MM-DD` | 空 |
| `--dateTo [value]` | 结束日期 `YYYY-MM-DD` | 空 |
| `--eventType [value]` | `1` 线下 / `2` 线上 | 空（不限） |
| `--qs [value]` | **按活动名称关键词过滤** | 空 |
| `--limit [value]` | 返回条数 1–50 | 20 |

```bash
# 线下 + 垂直技术词（产业情报雷达的标准姿势）
opencli --profile v6pz9gjx huodongxing events --qs "计算成像" --eventType 1 -f json

# 城市 + 时间窗
opencli --profile v6pz9gjx huodongxing events --qs "光谱" --city "深圳" \
        --date 2026-09-01 --dateTo 2026-12-31 --limit 20 -f json
```

### ⚠️ `--qs` 是按活动**名称**匹配，不是全文检索

这条决定了关键词策略：**议题词必须以会议起名的方式出现**才命中。
「计算成像」「微型光谱」「材料基因工程」这类**会被写进会议标题**的词有效；
描述性长句、痛点表述、公司名一律搜不到（它们只出现在正文/议程里，`--qs` 看不见）。

`--tag` 走的是平台自己的标签体系（如 `AI`），与 `--qs` 是两套维度，**可以组合用来降噪**——
两者 Jobs 侧此前只用了 `--qs`，`--tag` 未实测，值得试一轮。

## 输出结构

Output columns：`rank, id, title, time, eventType, city, location, organizer, url`

**注意输出里有什么、没有什么**：

| 有 | 没有（必须二段式再取） |
|---|---|
| 活动名、时间、线上线下、城市、场地、主办方、详情页 URL | 赞助商 / 展商名录、演讲嘉宾、议程、票价、报名人数 |

→ 标准两段式：
```
events 拿索引 → 筛掉噪声 → 取 id/url → opencli browser open/extract 穿透详情页
                                        （赞助商区块 / 议程表 / 嘉宾卡片）
```
详情页里大型展会的展商名单**常嵌在第三方展商系统的 iframe 里**，父页面抓不到 ——
改从正文里的外部官网链接（如 `csoe.org.cn`、CIOE 官网）转二级抓取。

## 反爬与节奏

| 项 | 实测 |
|---|---|
| 反爬厂商 | 未检出前置第三方反爬 |
| 限流表现 | 撞「当前访问人数过多，请休息片刻重试 / ERROR CODE: ...」busy 页 |
| v1.8.6 行为 | 误报 `EMPTY_RESULT`（适配器不识别该文案）—— 会被当成"这个词没搜到" |
| v1.8.7 行为 | 正确报 `COMMAND_EXEC: temporary busy/access page`，并自动在同一会话重试一次 |
| 安全节奏 | **单次调用间隔 15–30s**；本机 4 次密集探测即持续限流，**冷却以小时计** |
| 降级 | `--site-session persistent` 保住浏览器上下文；再不行转 WebFetch 打学会/展会官网交叉核验 |

> busy 页在 v1.8.6 上表现为空结果，这是**典型的静默失败**（data-quality-checklist.md 第 7 类"反爬限流"）。
> 本机已是 v1.8.7，会明确报错；**但如果哪天回滚或换机，空结果不等于关键词无效**。

## 踩坑

| 坑 | 现象 | 应对 |
|---|---|---|
| busy 页被当成空结果 | v1.8.6 报 `EMPTY_RESULT` | 升 v1.8.7；或看到连续空结果先当限流处理 |
| iframe 展商名单 | 详情页父级抓不到完整展商 | 提取正文里的外部官网链接，转二级抓取 |
| 企业注册名 ≠ 展会品牌名 | 展会挂 `Siminics`、`UPOLabs`，库里存中文实体名 | 精确比对会假阴性，**排重前必须先过中英文别名表** |
| 泛词把噪声灌满 | `人工智能`/`大数据` 搜出招商加盟、销售培训 | `--qs` 只认标题 → 用垂直复合技术词；噪声过滤属调用方职责 |

## 适用判断

**用**：按会议标题能命中的垂直技术议题，拿会议索引 → 穿透详情页取赞助商/嘉宾/议程。
**不用**：全文检索、公司名反查、任何指望适配器直接给出人和公司的场景（输出列里没有）。
