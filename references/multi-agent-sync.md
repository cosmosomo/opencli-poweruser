# 多智能体副本协作：版本收敛、特性回灌与冲突合并

> 同一台机器上会有多个智能体（Claude Code / 豆包 / 千问 / AntiGravity …）各持一份本 skill。
> 它们独立读写、独立推送，于是必然出现三件事：**版本不一致、新特性只进了一份、冲突不知道怎么合**。
> 这份文件就是处理这三件事的规程。**本机各副本的真实路径清单在 `LOCAL.md`「本机 skill 副本总账」一节**。

---

## 一、副本角色模型：谁能写，谁只读

副本不是平等的。混乱几乎都来自"每份都能写"。

| 角色 | 谁 | 能否改 | 怎么同步 |
|---|---|---|---|
| **canonical（权威）** | 一个 git 克隆，指定为唯一权威 | ✅ 改这里 | `pull --rebase` → `push` |
| **git 副本** | 智能体的 skill 加载目录，本身是 git 克隆 | ⚠️ 可改，但**必须当场提交并推送** | `pull --ff-only` |
| **托管副本** | 由宿主 App 导入管理、不是 git（如 SkillImport 类） | ❌ 只读 | 从暂存目录整体覆盖导入 |
| **归档快照** | 某次备份 | ❌ | 不同步，只作回溯 |

**为什么 git 副本用 `--ff-only`**：它拒绝一切需要合并的情况。副本上有人偷偷改了东西没提交，
`ff-only` 会直接失败并报出来，而不是悄悄合并或覆盖——**失败是特性，不是故障**。

## 二、每天一次的收敛流程

用一个同步脚本把"谁领先、谁落后、谁脏了"一次性打出来，按状态处置。核心动作只有四步：

1. **canonical 先收后推**：有未提交改动 → 先归纳成提交；再 `pull --rebase` 收别人的，再 push
2. **git 副本 `pull --ff-only`**：成功即对齐；失败说明该副本有本地改动，回到第 1 步把它提交掉
3. **托管副本比对内容哈希**：落后则从暂存目录重新导入（覆盖导入后目录 ID 可能变，定位要用通配符）
4. **公开发布**：只发方法论与踩坑经验，过脱敏器后推公开仓

### 状态与处置对照

| 现象 | 含义 | 处置 |
|---|---|---|
| canonical 有未提交改动 | 上个会话的经验没落库 | 按 `EVOLUTION.md` 规范写提交信息，commit + push，**重跑同步** |
| `pull --rebase` 冲突 | 两侧都改了同几行 | **绝不 force push、绝不 reset --hard**。只读看清双方各写了什么；都是 markdown 追加式章节就保留双方、重编号、更新日期行，再 `rebase --continue` |
| 副本 `pull --ff-only` 失败 | 该副本有未提交改动或已分叉 | 先把它的改动提交推送，再同步。**别用 `checkout --` 图省事，那是在删别人的经验** |
| 副本出现凭据类文件（cookie/token） | 有人把登录态落盘到了 skill 目录 | 立刻移出仓库目录，**绝不提交上云** |
| 副本 remote 指向错仓 | 曾发生过私有内容差点推进公开仓 | `git remote -v` 核对后 `set-url` 改回 |

## 三、新特性传不到所有副本：怎么发现、怎么回灌

**症状**：某个智能体加了新适配器卡或新脚本，只有它自己那份有；其他副本继续用旧知识踩老坑。

**根因**：那份改动**没提交**，或提交了但别的副本没同步。

**发现**（定期做，不要等出事）：

```bash
git fetch --all --prune
git log --oneline --all --graph -20                 # 谁在哪条线上写了什么
git log --oneline --all -- <某文件>                 # 这个文件在哪些分支被动过
git branch -r --no-merged main                      # 哪些分支的内容还没并回主干
```

**回灌**：
- 副本有未提交经验 → 在该副本就地提交推送，其余副本 `pull --ff-only` 自动拿到
- 副本落后但干净 → 一条 `pull --ff-only` 解决
- 托管副本（非 git）→ 从暂存目录整体覆盖导入，**没有增量手段，只能整体覆盖**
- 已经分叉太久 → 按第四节做语义并集

**判断"是否已覆盖所有副本"的唯一标准**：所有 git 副本的 HEAD 一致，且托管副本的内容哈希与暂存一致。
别用"我记得同步过"代替实测。

## 四、冲突合并：git 合不了散文

代码冲突 git 能帮你，但本 skill 的主体是**散文型经验**（渠道卡、踩坑条目、速查表行）。
两个智能体各写一段关于同一个适配器的经验，git 只会报"两边都改了这几行"，**合并要靠语义**。

### 原则：默认取并集，不做取舍

两边写的通常都是真的，只是各自观察到了不同侧面。

> 实例（2026-09-18 速查表 github 行）：
> A 版写「适配器只有 whoami/login 两条，拿不到仓库内容」，B 版写「Python urllib 中文搜索需 URL encode」。
> **合并结果同时保留两句**，只删真正重复的措辞。删掉任何一句都是丢经验。

### 三种情形的处置

| 情形 | 处置 |
|---|---|
| **互补**（各说一面） | 取并集，合成一条，保留双方的限定词与 n 值 |
| **同名新文件各写一版**（内容几乎零重合） | 先把其中一版挪到 `local/pending-merge-<日期>/`（`local/*` 被 .gitignore 排除，安全），再逐条做并集；**别直接覆盖** |
| **结论冲突**（同一件事说法相反） | **不许私自取舍**。列出双方证据与样本量报给用户；若一方是 n=1 观察、另一方是多轮验证，按 `channel-probing.md` §4.5 的证据分级标注，而不是删掉弱的那条 |

### 提交纪律：别把别人的未提交改动卷进你的提交

副本里常躺着上个会话没提交的 WIP。你要提交自己的修复时：

```bash
cp <文件> <备份>                      # 存下 WIP 版
git checkout -- <文件>                # 取回 HEAD 版
# 在 HEAD 版上打你的补丁
git add <文件>                        # 暂存区 = HEAD + 你的补丁
# 把同样的补丁打到备份的 WIP 版上，再拷回工作区
cp <备份> <文件>                      # 工作区 = WIP + 你的补丁
```

提交后：你的提交只含你的改动，WIP 仍原样留在工作区等主人处理。
`git diff --cached --stat` 与 `git diff --stat` 各看一眼确认分离干净。

**变基前务必先 `git diff > <某处>/wip.patch` 备份**，未跟踪文件另外拷走——
`pull --rebase` 遇到同名未跟踪文件会直接拒绝或覆盖。

## 五、自维护约定（这份总账靠智能体自己养）

**你正在使用的副本，如果不在 `LOCAL.md` 的「本机 skill 副本总账」里，就把它加上再继续干活。**

登记一行需要四项：

| 项 | 怎么取 |
|---|---|
| 路径 | 你的 skill 加载目录的绝对路径 |
| 宿主 | 哪个智能体在用（Claude Code / 豆包 / 千问 / …） |
| 类型 | git 克隆 / 宿主托管（非 git）/ 静态快照 |
| 角色 | canonical / git 副本 / 托管副本 / 归档 |

同样地，发现**本机还有别的 skill 没被登记**（尤其是没有任何版本控制的自建 skill），
也在总账里补一行并标注风险。没人会来提醒你——**看到缺口就补，是每个智能体的分内事**。

改完总账要提交推送，否则下一个智能体看不到。

---

## 六、铁律

1. 永不 `git push --force`——这是唯一能真正抹掉别人提交的操作
2. 永不用 `reset --hard` / `checkout --` 处理分叉，那是在删经验
3. **会话结束前必须提交**。未提交的改动对其他智能体完全不可见，也最容易被误删
4. 机器专属文件（本机路径、登录昵称、cookie/token）只留在私有侧，永不进公开仓
5. 判断不了就停下报给用户，别猜

## 七、已知坑

| 坑 | 教训 |
|---|---|
| 两个智能体各写了同名的四张渠道卡，内容几乎零重合 | 新建文件前先 `git fetch --all` 看远端有没有人建过 |
| 手改公开副本而不进脱敏规则表 → 下次同步被私有内容覆盖回来 | 脱敏修复要进规则表，不能手改 |
| 脱敏扫描器只扫 `.md/.js/.py`，漏了 `.ps1`，新脚本差点带本机路径发出去 | 新增文件类型时同步扩展扫描范围 |
| 合并正则里的反斜杠转义导致 grep 静默少匹配，漏报泄露 | 敏感扫描用逐模式独立 grep，别写合并正则 |
| 某副本 remote 曾误指向公开仓 | 每次同步核对 `git remote -v` |
