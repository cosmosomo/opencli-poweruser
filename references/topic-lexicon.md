# 议题词典方法论（Topic Lexicon）

> 验证日期：2026-09-12
> 来源：Agent Harness 领域调研实战（小红书 11 组关键词 → 58 篇去重 → 51 篇全文精读 → 130+ 词条词典）
> 用途：把"关键词"从一次性搜索弹药升级为**带认知评估、可跨议题复用的词典资产**
> 适用：任何前沿/快速演化领域的议题调研

---

## 〇、核心认知模型

人类调研的真实过程不是"想好关键词去搜"，而是一个**认知闭环**：

```
脑中已有词汇 → 搜索（探针）→ 结果里出现陌生词 → 反查理解 → 认知变立体
      ↑                                                          ↓
      └──────────── 带着更丰富的词汇继续顺藤摸瓜 ←────────────────┘
```

最终沉淀下来的不是搜索结果，而是**脑中那张带评估的词汇表**：哪些词更新、更热门、更前沿、更直击本质、更契合当下需求。这张表决定下一次调研的起点和方向。

**本方法论的目标就是把这张"脑内表"外化成文件**，使其可积累、可复用、可纵向追踪。

三条基本判断：

1. **词是探针，不是答案**。第一轮关键词只用来"钓"出陌生词，命中率低是正常的。
2. **search 结果有系统性热词偏差**。平台按热度排序，外层冷门词在标题层几乎不可见，只能靠**精读全文 + 标签全扫**发现。
3. **外层词信息密度常常高于热词**。`inputModalities`、`project trust ≠ sandbox`、"星标和装机是两张表"这类 n=1 的词，单条就能改变对整个领域的判断。

## 一、AI 认知盲区自觉（最高优先级，硬规则）

> **任何 AI 都必须清楚：自己并不知道真正的前沿词汇。**

这是本方法论区别于普通关键词策略的根本前提。

### 1.1 为什么必须自觉

AI 的词汇知识截止于训练数据。一个领域越前沿，AI 的先验词汇越不可靠：

| 情形 | 含义 | 对策 |
|---|---|---|
| AI 认识且能流畅解释 | 该词已进入训练语料 → **大概率已主流化或过时** | 可用，但不要指望靠它发现前沿 |
| AI 认识但解释含糊 | 词存在但语境已变（改名/换含义） | 必须在语料里核对当前用法 |
| **AI 不认识，但语料高频** | **最强前沿信号** | 最高优先级：立即反查 + 精读 |
| AI 不认识，语料也低频 | 真长尾或私人黑话 | 记录，暂不投入配额 |

**推论**：只用 AI 已知词汇做搜索，会系统性错过最新进展——因为"最新"的定义就是"还没进训练数据"。

### 1.2 五条操作规则

1. **开工先声明盲区**：调研开始时明确写出"我对本议题的词汇知识截止于训练数据，可能落后 N 个月；下列关键词仅为探针，不代表领域全貌"。
2. **词典必须标注先验状态**：每个词条标 `AI先验: 认识 / 模糊 / 不认识`。这是判断"前沿度"的第一手依据。
3. **强制第二轮**：第一轮搜完后，必须从语料提取 AI 不认识的词，反查含义后再搜一轮。只做一轮 = 只拿到 AI 已知的世界。
4. **警惕"过时词陷阱"**：AI 熟悉但语料显示已改名/已废弃的词要单独标记（本次案例：`Code Mode` 已改名 `PTC Mode`；`mem0` 星标 6.4 万但不接 dsh）。
5. **不认识的词优先精读**：配额有限时，"AI 不认识 + 语料高频"的笔记排在"AI 认识 + 高赞"之前。

### 1.3 本次实战的盲区样本

| AI 先验 | 词 | 说明 |
|---|---|---|
| 不认识 | `inputModalities` | DSH 模型能力声明字段，只能从笔记[14]发现 |
| 不认识 | `PTC Mode` | 原名 Code Mode，**改名这件事本身就是盲区**（训练数据只有旧名） |
| 不认识 | `.dshpreset` / `oh-my-dsh` / `archmap` / `parallel-dispatch` | 全新专有名词 |
| 不认识 | `PenguinHarness` / `QwenPaw` / `Prime Agent` / `nono` | 新入局玩家 |
| 模糊 | `时空可组合性` / `反应式余效应` | Cordis 概念，但"DeepSeek 用它"是训练后的事 |
| 认识但已过时 | `Code Mode`、`mem0`（就 dsh 生态而言） | 需标"已改名/不适用" |

## 二、词典七栏骨架（可直接套用于新议题）

| 栏 | 内容 | 作用 | 本次实例 |
|---|---|---|---|
| ① 核心词层 🔥 | 领域入口词、总公式 | 定义议题边界 | Harness、Agent=Model+Harness、DSH、Pi、Cordis |
| ② 机制概念层 | 范式/原理/设计取舍 | 理解"为什么" | 时空可组合性、可逆效应、事件日志投影、Turn Snapshot |
| ③ 阵营专有层 | 各产品的独有名词 | 区分路线 | pi-ai、Bot Mode、万神殿、首轮锚定、思维路由 |
| ④ 生态赛道层 | 插件名/项目名/工具名 | 摸产业生态 | memsearch、EverOS、OpenViking、dsh-context |
| ⑤ 学术基准层 | 论文名/指标/漏洞号 | 找硬证据 | PRISM、HarnessForge、Polar、Composio 4.3x、QVD-2026-57410 |
| ⑥ 社区叙事层 | 梗/隐喻/情绪句式 | 抓真实态度 | 拿跑车底盘当出租车开、精致的技术自 High、割韭菜 |
| ⑦ 平台标签层 | 话题标签 | 看自我命名进行时 | #harness_engineering #AgentRuntime #自进化AI |

**用法**：新议题先搭七栏空骨架，再用探针词填第①栏，其余六栏靠递归捕获逐步填满。第⑥⑦栏最容易被忽略，但对判断"圈子情绪"和"命名是否定型"不可替代。

## 三、五维评估（脑内评估的外化）

每个词条按五个维度打分/标注，这是词典区别于普通词表的核心：

| 维度 | 判据 | 记录方式 |
|---|---|---|
| **热度** | 语料频次 n、点赞数、跨笔记出现篇数 | `n=X`（脚本实扫，不靠感觉） |
| **新鲜度** | 首次出现时间 vs 领域起点；是否仍在改名 | `首见 YYYY-MM`；改名标 ⚠️ |
| **前沿度** 🔮 | 是否指向未定型的东西：单一信源、英文先行中文未译、AI 不认识、命名还在争 | 🔮 标记 + AI先验状态 |
| **本质度** ⚙️ | 是否直击机制/因果，而非营销包装：能用一句话解释"为什么这样设计" | ⚙️ 标记 |
| **契合度** | 与当前调研目标的匹配度（同一词典服务不同任务时打分不同） | 需求侧备注 |

**热度分层图例**（词典正文用）：

| 标记 | 含义 | 判据 |
|---|---|---|
| 🔥 核心 | 领域入口词，讨论必出现 | n≥40 或用户给定种子词 |
| ♨️ 常用 | 圈内高频 | n 5~40 |
| ❄️ 外层 | 少数人使用的深水区术语/黑话/新造词 | n≤5 或仅单一信源 |

**升降级判据**（让词典可维护，不做只增不减的垃圾场）：
- ❄️ → ♨️：下次同语料扫描 n≥5，**或**多平台（知乎/HN/GitHub issue）交叉命中
- ♨️ → 🔥：成为讨论前提（不再需要解释）
- 任何层 → 标 `已废弃(日期)`：改名/项目停更/被替代（保留不删，见 EVOLUTION.md 维护原则）

**最高价值区**：`❄️低热 + 🔮高前沿 + ⚙️高本质` —— 别人还没搜过、但直指机制的词。这是词典真正的产出。

## 四、顺藤摸瓜的递归与剪枝

### 4.1 递归流程

```
第 0 轮：AI 已知词（探针）+ 用户给定种子词
   ↓ search
第 1 轮：从标题提取新词 → 入词典 → 五维评估
   ↓ 剪枝后 search（只搜值得搜的）
第 2 轮：从精读全文 + tags 全扫提取外层词 → 入词典
   ↓ 反查 AI 不认识的词（WebSearch / 官方文档 / GitHub）
第 3 轮：用反查得到的准确术语再搜 → 收敛
   ↓
词典定稿 + 分析报告
```

### 4.2 剪枝规则（不是所有新词都值得再搜）

| 词的特征 | 处理 |
|---|---|
| 🔥高热 + ⚙️高本质 | **必搜**（主干） |
| ❄️低热 + 🔮高前沿 + ⚙️高本质 | **必搜**（宝藏区，竞争最小） |
| AI 不认识 + 语料高频 | **最高优先级**（前沿信号） |
| 高热 + 低本质（教程流量词：保姆级/一条视频讲清楚/从零到一） | 记录不搜，或仅用于判断内容生态 |
| 低热 + 低本质（个人黑话、错别字变体） | 记录不搜 |
| 同义变体（大小写/中英/缩写） | 合并为一条，变体列入"别名"列 |

### 4.3 配额分配：词典分层 ↔ 反爬成本联动

这是本方法论最直接的运营价值（小红书实测数据）：

| 词层 | 走哪个通道 | 实测成本 | 依据 |
|---|---|---|---|
| 🔥 核心词 | `search` | 贵：30 秒/词，第 6 词即累积限流 | search 是高频爬虫入口，风控最严 |
| ❄️ 外层词 | `note` 精读 | 便宜：7 秒/篇，51 篇连打零风控 | note/comments 模拟正常浏览行为 |

**结论**：先用少量 🔥 词通过 search 攒下笔记列表（省配额），再用大量 ❄️ 词通过 note 精读补全认知（不限量）。本次限流后靠"转 note 精读"完成调研，正是这个分配。

## 五、标签扫描法（捞外层词的技术手段）

search 标题层看不到外层词，必须从**精读正文 + tags 字段**捞。

**tags 是被严重低估的信源**：它是作者自己打的分类标签，反映圈子的自我命名，且不受搜索热度排序影响。

```python
# scripts/lexicon_scan.py 的 tags 模式
tags = Counter()
for f in RAWD.glob("*.json"):
    o = flatten(json.loads(read_json(f)))          # note 返回 [{field,value}]，需摊平
    for t in re.split(r"[,，]\s*", o.get("tags", "") or ""):
        if t.strip():
            tags[t.strip()] += 1
```

本次扫描产出（51 篇 → 143 个标签）：
- **自我命名进行时**：`#harness_engineering`(2) `#AgentEngineering`(2) `#AgentRuntime`(1) `#AI工程化`(1) `#自进化AI`(1) —— 领域还没定下叫什么，标签战未定，这本身就是"前沿"的证据
- **search 永远搜不到的外层词**：`#REDskill`（垂直领域 Harness 系列）`#ToolCalling` `#Pi拆中学`
- **流量词识别**：`#howto用好AI`(9) `#AI新手村`(6) `#vibecoding`(4) → 判低本质，记录不搜

## 六、词典的生命周期与跨议题复用

### 6.1 纵向追踪（议题雷达）

定期复跑 `scripts/lexicon_scan.py`，对比 n 变化：

| 信号 | 含义 |
|---|---|
| ❄️ 词 n 上升 / 升 ♨️ | 概念正在扩散（如英文外围源术语进入中文语料） |
| 🔥 词 n 下降 | 声量衰退（本次样本："大家还在用 Hermes 吗" 748 赞 / **381 评论**，发帖日正是 DSH 发布后 10 天） |
| 新词首次出现 | 领域有新玩家/新概念 |
| 词被改名 | 项目进入不稳定期（Code Mode → PTC Mode） |

**没有词典就没有纵向对比**——每次调研的关键词都从零拍脑袋，趋势无从谈起。

### 6.2 新议题冷启动

七栏骨架 + 五维评估表直接套用，先填第①栏核心词，再走递归流程。比临场设计关键词矩阵快得多。

### 6.3 跨议题迁移

相邻议题的词典互相引用（Agent Harness ↔ RAG ↔ 多模态 Agent ↔ AI 编程工具）。同一词在不同议题词典里的**契合度**打分不同，但热度/前沿度可继承。

### 6.4 词典 = 跨平台翻译层

同一概念在不同平台的表达形态不同，词典的"别名/变体"列天然就是映射表：

| 平台 | 形态 | 例 |
|---|---|---|
| 小红书 | 口语梗 | "真的有点上头了"、"死磕" |
| 知乎 | 术语长文 | "时空可组合性"、"如何评价 X" |
| GitHub | 代码符号 | `dshpreset`、`inputModalities` |
| HN/arXiv | 英文原名 | Spatiotemporal Composability、PRISM |

→ 跨平台调研时，**不要直接翻译关键词**（research-sop.md §6 已验证），查词典的别名列取对应平台的形态。

### 6.5 反哺其他 SOP

| 目标 SOP | 词典贡献 |
|---|---|
| 舆情/风评调研（research-sop.md §六） | 第⑥栏社区叙事层 = 贴议题的负面触发词库，比通用"踩坑/吐槽/避雷"精准（本次："割韭菜""排队""精致的技术自 High""会变化离会进步还很远"） |
| 数据质量检查（data-quality-checklist.md） | `AI先验=不认识` + 单一信源的词 = "单源待校验"红旗，防止把一家之言写进结论 |
| B站 ASR 工作流（bilibili-asr-workflow.md） | 词典 → bilibili search 选片 → 字幕/ASR → 入库；转写文本反哺词典发现长尾口语词 |
| 新站点探索（new-site-exploration.md） | 第③④栏玩家名录 = 待覆盖站点清单，指导是否写新适配器 |
| 招聘/技能信号扫描 | 第①栏 = JD 硬技能要求，第⑥栏 = 面试话术词 |

## 七、词典文件规范

### 7.1 存放位置

**词典是议题的数据产物，属 content 层，不进 skill 仓库**（EVOLUTION.md §1.2：单次任务的具体数据不记录）。

- 词典本体 → 调研目录：`research/<日期>-<议题>/<议题>领域词语档案.md`
- 方法论（本文件）→ skill：`references/topic-lexicon.md`
- 扫描脚本 → skill：`scripts/lexicon_scan.py`（参数化，不含具体议题词）

### 7.2 词典正文必备字段

```markdown
| 词条 | 变体/别名 | 释义 | 热度(n) | AI先验 | 前沿🔮 | 本质⚙️ | 来源 |
```

- `n` 必须脚本实扫，不靠感觉估
- `来源` 用 notes_inventory 序号或标"外围信源"（WebSearch/arXiv/官方文档）
- 外围信源词必须标 `n=0 外围`，与语料实测词区分开（数据质量纪律）

### 7.3 配套文件

| 文件 | 作用 |
|---|---|
| `raw/kw*.json` | 各关键词 search 原始结果 |
| `raw/notes/*.json` | 精读全文（摊平前的原始结构） |
| `raw/notes_inventory.tsv` | 去重清单（i/likes/pub/author/id/title/url） |
| `<议题>领域词语档案.md` | 词典本体 |
| `term_freq` / `scan_tags` 输出 | 频次与标签统计（用 scripts/lexicon_scan.py 复跑） |

## 八、检查清单（每次议题调研结束自检）

- [ ] 开工时是否声明了 AI 词汇盲区？
- [ ] 词典是否按七栏骨架组织（尤其没漏第⑥社区叙事、第⑦平台标签）？
- [ ] 每个词是否标了 `AI先验` 状态？
- [ ] 是否跑了第二轮（从语料提取陌生词后反查再搜）？
- [ ] 频次 n 是脚本实扫还是拍脑袋？
- [ ] 是否识别并标记了"AI 认识但已过时/已改名"的词？
- [ ] tags 是否全扫过（不只是看标题）？
- [ ] 🔥/❄️ 词的 search / note 配额是否分配合理（有没有浪费 search 配额在低本质词上）？
- [ ] 词典是否留在调研目录（content 层），只把方法论沉淀进 skill？
- [ ] 是否记录了本次的新词捕获路径，供下次纵向对比？
