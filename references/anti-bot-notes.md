# 站点反爬/反调试识别与应对速查

> 建立日期：2026-08-28
> 来源：BOSS 直聘反爬调研（CSDN/腾讯云/掘金/知乎/V2EX/影刀 RPA/GitHub/抖音逆向教学）+ 小红书限流实测
> 用途：任何浏览器桥接适配器遇到「页面闪烁 / 强制登出 / stale page identity / 返回空」时，先查本文件判断是否被反爬
> 配套：adapter-boss.md（BOSS 专项）、adapter-xiaohongshu.md（小红书专项）、pitfalls.md（通用踩坑）

## 一、核心判断：如何识别「站点在反爬」

| 现象 | 可能原因 | 判断方法 |
|---|---|---|
| 页面一直闪 / 自动刷新 | **反调试探测器命中** → `location.reload()` | 检查是否打开 DevTools/CDP；正常浏览器是否稳定 |
| 打开 F12 / DevTools 就闪退或清空页面 | 反调试（console 序列化 / 断点计时 / 窗口尺寸检测） | 用「浏览器菜单打开」而非快捷键验证 |
| 自动化工具一连接就 stale / detached | CDP 特征（`navigator.webdriver`/调试端口）被探测 | 查看错误是「页面句柄过期」还是「连接断开」 |
| 连续请求后返回空数组 / 空结果 | 限流或风控（不一定报错） | 冷却 60s 后用 `feed --limit 5` 探活区分 |
| 登录态莫名丢失 / 强制登出 | 后端 token 熔断（清 cookie） | 检查 `set-cookie` 是否为 `Expires=1970` |

**共性规律**：只要「CDP/DevTools 驱动浏览器」，就同时暴露三类自动化特征——
`navigator.webdriver=true`、调试端口（如 `127.0.0.1:9222`）、`chrome.runtime` 扩展痕迹。站点检测到任一类即可判定自动化。

## 二、常见反爬手段清单（识别用）

| 层级 | 手段 | 识别特征 |
|---|---|---|
| 调试层 | 8 种 DevTools 探测器 | 无限 debugger / console 序列化 / outerWidth-innerWidth>160 / Performance 计时 / eruda/vConsole 检测 |
| 入口层 | 验证码/滑块 | headless 重定向到 CAPTCHA；极验/网易易盾 |
| 渲染层 | 字体反爬 | DOM 文本为乱码（薪资/数字用动态字体渲染） |
| 协议层 | 动态 token | cookie/参数含时效 token（如 `__zp_stoken__`），短有效期 |
| 参数层 | 接口签名 | URL 带签名参数（如 `_l`/`ka`/`utrace`），每请求变化 |
| 行为层 | 行为指纹 | 鼠标轨迹、停留时长、滚动深度被采集 |
| 设备层 | 浏览器指纹 | Canvas/WebGL/字体列表熵值检测 |
| 网络层 | TLS+IP 风控 | JA3 指纹、IP 频控、地域突变、数据中心 IP 标记 |

## 三、应对策略（降频保号优先）

### 3.1 通用节奏控制（适用所有站点）
- 单批 limit ≤ 10，单任务页数 ≤ 3，避免连环请求
- 请求间隔 12-25s **随机延迟**（不要固定值，防时序规律识别）
- 可模拟行为：随机滚动、鼠标抖动、15% 回滚、随机停顿
- 连续 2 次异常信号（空结果/闪退/登出）→ 立即停手，冷却 ≥ 60s，用轻量命令探活

### 3.2 停手信号
| 信号 | 处理 |
|---|---|
| 连续 2 次返回空数组 | 冷却 ≥ 60s，`feed --limit 5` 探活区分限流/关键词 |
| 页面闪烁/自动刷新 | 停止操作，重建持久会话，降频 |
| 强制登出 | 停止 ≥ 数小时，检查登录态 |
| `stale page identity` | `--window foreground --site-session persistent` 重建会话 |

### 3.3 重建持久会话（后台运行基础）
```bash
# 遇到 stale 时跑一次（首次必须 foreground）
opencli <adapter> search --limit 1 --window foreground --site-session persistent -f json
# 后续后台运行
opencli <adapter> <command> --window background --site-session persistent -f json
```

## 四、技术路线评估（选路指南）

| 路线 | 稳定性 | 合规性 | 适用 |
|---|---|---|---|
| **浏览器插件只读 DOM** | 高 | 灰（通常可接受） | 用户正常登录浏览，插件只读已渲染数据 → 长期稳定 |
| **截图 + AI 视觉分析** | 高 | ✅ | 手动浏览截图 → AI 解析，零检测风险 |
| **CDP 复用登录态**（低频单次） | 中 | ⚠️ | 单次采集可跑通，长期有被封风险 |
| **App 端签名逆向** | 中 | ⚠️ | 无浏览器，但维护成本高（每日换逻辑） |
| **反检测浏览器**（stealth 等） | 低 | ❌ | 治标不治本，仍可能被行为分析识别 |
| **官方 API** | 理想 | ✅ | 需申请开放平台权限，最稳 |

**核心结论**：纯自动化（CDP/stealth）在强反爬站点长期不可行；「人机协作」（插件只读/截图+AI）是唯一长期稳定路径。

## 五、已确认站点反爬状态（实测/调研）

| 站点 | 反爬强度 | 已知手段 | 应对要点 |
|---|---|---|---|
| BOSS 直聘 | 🟥 工业级 | 反调试+动态token+行为指纹+后端熔断 | 低频单次 CDP 可跑，长期必登出；Firefox 方案已失效；详见 adapter-boss.md |

| ChatGPT 网页 | 🟥 特殊 | UI 改版致选择器失效（非反爬） | 适配器待修复，见 pitfalls.md |

## 六、合规提醒

- 以上内容仅用于识别站点防御机制、评估采集边界、保护账号安全
- 大规模抓取涉及法律风险（部分站点有维权手段），主流开源项目均标注「仅限个人研究、低频、尊重 robots/条款」
- 商业用途建议优先走官方 API / 授权合作
