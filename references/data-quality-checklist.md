# 数据质量检查清单

> 使用者视角：用 OpenCLI 采集数据后，如何验证数据是对的，而不是"看起来能跑"。
>
> 核心原则：**命令能跑通 ≠ 数据正确。** "字段有值"比"字段为空"更危险——空你会去查，有值你会直接用。

---

## 1. 为什么需要数据质量检查

OpenCLI 适配器返回数据时，可能出现以下情况：
- 命令执行成功，返回 200，JSON 格式正确
- 但字段值是错的、空的、污染的、单位错的、语义分歧的
- 你不仔细看就直接用，结果分析结论全错

**真实案例**：
- 小红书 `note` 命令不传完整签名 URL → 返回空数据，但不报错
- B站 `subtitle` 拿到的是自动生成字幕，不是人工字幕 → 内容有偏差
- 知乎 `answer-detail` 字段里混了 HTML 实体 → 显示乱码
- 职位搜索 `salary` 字段单位不统一（"20-30K" vs "20000-30000"）→ 统计错误

---

## 2. 11 种静默失败（使用者视角识别）

### 2.1 字段内容污染

**现象**：`description` 字段不为空，但里面混了 `"address: 上海 category: IT"` 之类明显不属于描述的片段。

**原因**：适配器用了 `.container.textContent`，把所有后代文字都吃进去了。

**检查方法**：
- 拿一条结果，把 `description` / `content` / `summary` 等长文本字段完整读出来
- 看有没有明显不属于该字段的片段（地址、分类、标签、面包屑）
- 和网页上的实际描述对比

**应对**：记录到 `references/adapter-<name>.md`，标注该字段有污染问题，使用时需清洗。

---

### 2.2 字段语义分歧（两个字段看起来都对）

**现象**：51job 有 `updatedate` 和 `publishDate`，东方财富有 `f10`（发行日）和 `f26`（上市日）。适配器随便选一个，你拿到的时间可能错位 1 个月。

**检查方法**：
- 看到两个相似字段（`createTime` vs `updateTime`、`publishDate` vs `updatedate`）时，不要假设
- 拿一条已知记录，和网页上的实际值对比，确认哪个字段是你要的
- 记录字段含义到 `references/adapter-<name>.md`

---

### 2.3 字段单位混淆（数值量级错）

**现象**：接口返回 `totalMarketCap: 128`（单位：亿元），你以为是元，差了 1 亿倍。

**常见错位**：

| 接口返回 | 网页显示 | 实际单位 | 错误用法 |
|---|---|---|---|
| `0.025` | `2.5%` | 小数（0-1） | 再 × 100 → 250% |
| `12800` | `1.28 万` | 元 | 不除 10000 → 12800 万 |
| `f152 = 2`, `price = 927` | `9.27` | 价格 = 原值 ÷ 10^f152 | 忽略 f152 → 927 |
| `likes: "1.2万"` | `12000` | 带单位字符串 | 直接当数字用 → NaN |

**检查方法**：
- 数值字段必须和网页上的显示值对比数量级
- 看到 `"万"` / `"亿"` / `"k"` 等单位后缀时，必须转换
- 百分比字段确认是 0-1 还是 0-100
- 记录单位到 `references/adapter-<name>.md`

---

### 2.4 等不够就抓导致空数据

**现象**：`opencli <adapter> search "关键词"` 返回空列表，但网页上明明有内容。

**原因**：SPA 页面 JS 还没加载完，适配器就抓了，拿到空 DOM。

**检查方法**：
- 返回空时，先在浏览器里手动打开页面确认有内容
- 重试一次，或加 `--limit` 小一点测试
- 记录到 `references/adapter-<name>.md`：该适配器偶发空返回，需重试

---

### 2.5 falsy `|| 0` 兜底静默

**现象**：`likes: data.likes || 0`。接口偶尔返回 `likes: null`（字段名改了或权限问题），适配器写成 0，你看到"所有帖子 0 赞"。

**检查方法**：
- 数值列全是 0 → 可疑，可能是兜底
- 拿一条热门内容，确认点赞数应该 > 0
- 记录到 `references/adapter-<name>.md`：该字段可能静默兜底为 0

---

### 2.6 登录态漂移 / 权限不足

**现象**：用未登录态采集需要登录的内容，返回空或部分数据，但不报错。

**检查方法**：
- 需要登录的平台（小红书、知乎、Reddit），先确认 `opencli <adapter> whoami` 返回 `logged_in: true`
- 采集到的数据量明显少于网页上看到的 → 可能是登录态问题
- 记录登录要求到 `references/adapter-<name>.md`

---

### 2.7 反爬限流 / 验证码

**现象**：前几次调用正常，后面突然返回空或报错。

**检查方法**：
- 连续调用后突然空返回 → 可能触发限流
- 在浏览器里手动访问页面，看有没有验证码
- 降低频率（同一适配器 ≤ 3 次/分钟），或加间隔
- 记录反爬特征到 `references/adapter-<name>.md` 和 `references/anti-bot-notes.md`

---

### 2.8 HTML 实体 / 编码问题

**现象**：文本里出现 `&#x27;` / `&amp;` / `\u003c` 等编码，或中文乱码。

**检查方法**：
- 长文本字段检查有没有 HTML 实体
- 中文字段检查有没有乱码（`锟斤拷` / `æ–‡å—`）
- PowerShell 读写文件指定 UTF-8
- 记录编码问题到 `references/adapter-<name>.md`

---

### 2.9 URL / 链接不完整

**现象**：返回的 URL 是相对路径（`/video/BVxxx`），不是完整 URL（`https://www.bilibili.com/video/BVxxx`）。

**检查方法**：
- URL 字段检查是否以 `http` 开头
- 相对路径需要拼接 host
- 记录到 `references/adapter-<name>.md`

---

### 2.10 分页 / limit 不生效

**现象**：加了 `--limit 50`，但只返回 20 条；或翻页后内容重复。

**检查方法**：
- 确认返回条数和 `--limit` 一致
- 翻页时检查有没有重复内容
- 记录分页行为到 `references/adapter-<name>.md`

---

### 2.11 字段缺失 / 列对不上

**现象**：文档说有 `author` 字段，但实际返回没有；或 `columns` 列表和实际返回的 keys 对不上。

**检查方法**：
- 拿一条完整返回，检查所有预期字段是否存在
- 缺失字段记录到 `references/adapter-<name>.md`
- 不要假设字段存在，使用前先检查

## 3. 数据采集后验证 5 步法

每次用 OpenCLI 采集数据后，按以下步骤验证：

### Step 1: 非空检查
- 返回列表长度 > 0？
- 核心字段（title/name/id/url）不为空？
- 全是空 → 回到第 2.4 / 2.6 / 2.7 节排查

### Step 2: 肉眼比对（最关键）
- 随机抽 1-3 条结果
- 在浏览器里打开对应页面
- 逐条对比：标题对不对？数字对不对？时间对不对？
- **这一步不能省。** 命令能跑通不代表数据对。

### Step 3: 单位和量级检查
- 数值字段和网页显示值对比数量级
- 百分比是 0-1 还是 0-100？
- 金额单位是元、万元还是亿元？
- 时间是 ISO 格式还是本地字符串？

### Step 4: 字段语义检查
- 两个相似字段，确认用的是对的那个
- 长文本字段有没有污染
- URL 是不是完整的
- 编码有没有问题

### Step 5: 记录经验
- 发现的问题记录到 `references/adapter-<name>.md`
- 新验证的平台更新 `references/verified-platforms.md`
- 反爬特征更新 `references/anti-bot-notes.md`
- 本机专属信息更新 `LOCAL.md`

## 4. 不同平台的特殊检查点

| 平台 | 特殊检查点 |
|---|---|
| 小红书 | `note` 必须传完整签名 URL（含 xsec_token）；点赞数可能是 `"1.2万"` 格式；图片下载需完整 URL |
| B站 | `subtitle` 可能是自动生成字幕；`summary` 是官方 AI 总结不是全文；番剧/PGC 视频字幕需特殊处理 |
| 知乎 | `answer-detail` 可能含 HTML 实体；长回答可能被截断；收藏夹需登录 |
| Reddit | 分数（score）可能被点赞数混淆；评论可能有 `[deleted]`；NSFW 内容需登录 |
| V2EX | 内容可能含 Markdown 语法；节点分类和标签可能不一致 |
| BOSS 直聘 | `security_id` 含特殊字符需双引号；薪资范围是字符串需解析；反爬严格，可能触发强制登出 |
| GitHub | 适配器只有 whoami；发现项目用 `github-trending`；API 有速率限制 |

## 5. 数据质量速查表

| 检查项 | 怎么查 | 发现问题怎么办 |
|---|---|---|
| 非空 | `result.length > 0` | 检查登录态、重试、检查反爬 |
| 标题正确 | 和网页对比 | 记录字段映射问题 |
| 数值量级 | 和网页对比数量级 | 记录单位，使用时转换 |
| 时间格式 | ISO vs 本地字符串 | 统一转换为 ISO |
| URL 完整 | 以 `http` 开头 | 拼接 host |
| 编码正常 | 无 HTML 实体/乱码 | 解码后使用 |
| 字段无污染 | 长文本无多余片段 | 清洗后使用 |
| 分页正确 | 条数 = limit，无重复 | 记录分页行为 |
| 登录态有效 | `whoami` 返回 logged_in | 重新登录 |
| 未触发反爬 | 无验证码/限流 | 降频，加间隔 |
